**Unification pitfall (new, worth knowing for R1/R3 and the port).** When a `ᵀ`-shaped hypothesis is
the only thing that fixes an implicit matrix of a `ᴴ` lemma, Lean can solve `Qᴴ =?= Mᵀ` by unfolding
`Mᵀ`. The lemma then comes out about `(fun j i => …)ᴴ` and later `rw`/`simpa` steps fail. Examples:
`frobSq_mul_left_of_orthonormal hUt` with `hUt : Uᵀᵀ * Uᵀ = 1`, and `frobSq_three_compressed_blocks_le_two_mul`
fed with `(mul_moorePenroseInverse_isSymm B : (B*B⁺).IsHermitian)` in an `IsSymm` slot. The fix is to
name the matrix: `(Q := Uᵀ)`, `(V := Vᵀ)`, `(Q := B * moorePenroseInverse B) (P := moorePenroseInverse A * A)`.
This happened in Sylvester, SpectralFrameWeights, EigenvalueTrace and PseudoinverseFrobeniusPerturbation.

The four `SpectralNormBounds` warnings (l.30/43/59/98 in γ1's report) are silenced with
`omit [DecidableEq m] in` (placed before the docstring). Omitting the instance there made it unused in
their downstream users too, so the warning cascaded. I silenced every new one inside the area the same
way. The affected theorems are: SpectralNormBounds (6), SpectralBounds (4), Net (5, one private),
EuclideanOperatorBounds (1), NuclearNorm (`specNorm_le_nuclearNorm`, `nuclearNorm_eq_zero_iff`),

uses. There was one: `Inequalities/KyFanNormToolkit` builds a structure from `@NLAlib.specNorm_le_nuclearNorm`
and `@NLAlib.nuclearNorm_eq_zero_iff`. Both now use the file's existing
`(by intros; apply …)` form. No other `@` use of an omitted theorem exists in `NLAlib` (grep).
