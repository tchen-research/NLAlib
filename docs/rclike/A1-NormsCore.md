## Split

The generalised file would have been about 930 lines, so it is split:

* `Matrix/Norms/Frobenius.lean` (Mathlib imports only): the definitions `frobInner`, `frobSq`,
  `frobNorm` and the whole Frobenius API: algebra, squared norm and norm, rows and dot products,
  row-wise Cauchy–Schwarz, Cauchy–Schwarz and the triangle inequality, and products with
  orthonormal-column factors.
* `Matrix/Norms/Core.lean` imports `Frobenius` (plus `Mathlib.LinearAlgebra.Matrix.Hermitian`):
  `specNorm`, the real Euclidean-length lemmas, and the spectral and mixed inequalities.

All 570 dependants import `Core`, so they still see every name. The declarations that moved
(module `NLAlib.Matrix.Norms.Core` → `NLAlib.Matrix.Norms.Frobenius`) have the same names. The
`module` fields in `atlas/atlas.json` are refreshed by the next `ExtractDecls` + `sync_atlas.py`.

**`specNorm_transpose` over 𝕜.** Mathlib has no `l2_opNorm_transpose`. New lemmas
`specNorm_map_star_le` and `specNorm_map_star` (`‖A.map star‖₂ = ‖A‖₂`) prove it. The proof bounds
the operator norm with `ContinuousLinearMap.opNorm_le_bound`, using
`(A.map star) *ᵥ x = star (A *ᵥ star x)` and the fact that entrywise `star` preserves the Euclidean
norm; equality follows by applying the bound twice. Then `Aᵀ = Aᴴ.map star` and
`Matrix.l2_opNorm_conjTranspose` give the result.

## Stayed real, and why

* `dotProduct_self_nonneg`, `mulVec_dotProduct_mulVec_eq_sum_sq`,
  `mulVec_dotProduct_mulVec_le_frobSq_mul`, `sum_diag_sq_le_frobNorm_sq`: these are real
  dot-product or real-square statements. Their general forms are the `star`/`norm` lemmas above,
  and Mathlib has `dotProduct_star_self_nonneg`.
* Euclidean length (`norm_eq_sqrt_dotProduct`, `sqrt_dotProduct_self_eq_norm`, `norm_eq_sqrt_sum_sq`,
  `sqrt_dotProduct_self_pos`, `sqrt_dotProduct_add_le`, `sqrt_dotProduct_sub_le`): these are about
  `EuclideanSpace ℝ` and `v ⬝ᵥ v`.
* `abs_dotProduct_mulVec_le_specNorm` (`|xᵀMx| ≤ ‖M‖₂ xᵀx`): the 𝕜 form with `re` belongs to stage
  C13 (it merges the complex twin).

## Not done here

* There is no `frobSq_eq_frobenius_norm_sq` (Mathlib's scoped Frobenius `‖A‖ ^ 2 = frobSq A` over 𝕜).
  Stating it in Core would need the `Matrix.Norms.Frobenius` scope next to the L2 scope (ambiguous
  `‖A‖`). The ℝ version already exists as `frobenius_norm_sq_eq_frobSq` in
  `Norms/ComplexFrobenius`. This belongs to C1, which merges that file:
  `frobenius_norm_sq_eq_sum_norm_sq` + `frobSq_eq_sum_norm_sq` give it in one line.
* No `open scoped ComplexOrder` was needed, because no statement has `0 ≤ (x : 𝕜)`.
* Atlas: the tags stay on the real corollaries, whose `atlas.json` formalizations have hand-written
  `usage` sentences. The general versions carry the same ids: `frobSq_eq_sum_norm_sq`,
  `frobSq_mul_left_of_conjTranspose_mul_self`, `specNorm_mul_conjTranspose_self`,
  `specNorm_sub_mul_conjTranspose_mul_le`, `specNorm_add_sq_le_of_mul_conjTranspose_eq_zero` with
  `norms-frob-spec`, and `specNorm_le_one_of_isHermitian_of_isIdempotentElem` with
  `projection-facts`. The `matrix-norms-def` usage text for `frobInner` still says `∑ᵢⱼ AᵢⱼBᵢⱼ`
  (D13, coordinator).
