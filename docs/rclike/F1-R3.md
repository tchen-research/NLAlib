## Observations for the coordinator

* **Unification hazard of the `ᴴ` statements at ℝ.** When an implicit matrix is determined *only*
  by a `ᵀ`-shaped hypothesis in a `ᴴ` slot that comes first (`pinvL_mul (h : IsUnit (Gᴴ * G))`,
  `specNorm_add_sq_le_of_mul_conjTranspose_eq_zero (h : X * Yᴴ = 0)`), Lean sometimes solves the
  `?Gᴴ =?= Mᵀ` problem with an eta-expanded lambda (`fun j i => …`). The proof term still
  elaborates, but a later `rw` cannot find the pattern. The fix is a named argument. Slots where the
  plain occurrence comes first (`mul_pinvR (h : IsUnit (G * Gᴴ))`) were fine.
* `isHermitian_transpose_mul_mul` has no alias, and its replacement takes its arguments in the
  opposite order. FunctionApprox uses it inside two **theorem statements** (`.eigenvalues`), now
  spelled `(show (Qᵀ * A * Q).IsHermitian from Matrix.isHermitian_conjTranspose_mul_mul Q hA)`.
  The port should restate these with a named Ritz matrix.
* The ℝ-only `SpectralNormBounds` lemmas `specNorm_mul_left_of_hasOrthonormalCols` /
  `specNorm_mul_transpose_right_of_hasOrthonormalCols` still take `Pᵀ * P = 1`. They are the main
  reason for the local `hXt` haves. They are leaf twins of `…_of_conjTranspose_mul_self`, a port item.
* Stale docstring references to removed names remain (not edited, freeze rule):
  Solvers/Kaczmarz/Core l.22, LowRank/Nystrom/SketchedRegression l.22–27,
  Sketching/Properties/SubspaceEmbedding/SubspaceEmbedding l.18–19, Krylov/Quadrature/GaussQuadrature l.32,
  RandomMatrix/Gaussian/InverseMoments/{FrobeniusMoments l.103, Mean l.28/232} (these name a lemma
  that still exists).
